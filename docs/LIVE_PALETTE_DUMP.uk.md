# Дамп палітри з DOSBox-X — стан реалізації (перевірено кодом і запуском)

Оновлено після підключення **98Bridge** (читання/запис HDI) і прямих прогонів
емулятора. Усе нижче або **перевірено**, або явно позначено як **неперевірене**.

---

## 1. Що працює (і як цим користуватися)

### A. Жива палітра з емулятора — `PC98 DACPAL`

У дебагері DOSBox-X є **недокументована** команда (у `HELP` її немає, у меню
теж, тому «функції здампити палітру не видно»):

```
Analog 16-color DAC palette (RGB): 00: 000 00a 0a0 0aa-a00 a0a aa0 aaa
                                   08: 555 55f 5f5 5ff-f55 f5f ff5 fff
VGA DAC palette (RGB): 00: 000000 010101 ...
Digital 8-color DAC palette (RGB): 00: 01234567
```

Запускати її можна **ззовні**, без ручного дебагера: `mcp_server = <порт>` у
конфізі змушує DOSBox-X під'єднатися TCP-клієнтом до `127.0.0.1:<порт>`, а
`EXEC` виконує будь-яку команду дебагера.

```powershell
# 1) підняти слухача (він надрукує порт)
python tools\dosbox_mcp_palette.py --listen 2999 --save out\pal\game.pal `
       --preview out\pal\game_preview.png

# 2) у конфізі гри додати mcp_server = 2999 і запустити DOSBox-X
```

Перевірено: `PING -> PONG`, `EXEC PC98 DACPAL` повертає палітру, парсер пише
`.pal`. Працює і проти **вже запущеної** гри: `python tools\mcp_probe.py
--listen 2999 --command "PC98 DACPAL"`.

Додатково перевірено: `EXEC INP 0xa8` -> `Result: 0` (читання портів працює),
`EXEC MEMDUMPBIN A000:0000 4000 vram.bin` -> дамп текстової VRAM у файл на
хості (так я прочитав екран завантаження гостя).

### B. Палітра зі скріншота (резервний шлях, без конфігів)

```powershell
python tools\pal_from_shot.py capture\game.raw1.png -o out\game.pal --fmt all
```

## 3. Три факти, які я довів експериментально

1. **Гість пише в HDI, і хост це бачить.** Чистий тест: `IMGMOUNT C … -t hdd
   -size 512,17,4,320` + `ECHO HOST-WRITEBACK-TEST > WBTEST.TXT` + `EXIT`;
   DOSBox-X вийшов сам (код 0), образ змінився, `WBTEST.TXT` читається з образу.
   **Умова: вихід емулятора має бути коректним** — при `kill -force`
   незаписані зміни губляться.
2. **98Bridge читає/пише цей HDI.** `AUTOEXEC.BAT`, витягнутий через 98Bridge,
   побайтово збігається з раніше розпакованою копією (SHA-256 збіг).
3. **Інжектор не псує образ.** `inject_paldump.py verify`: серіалізатор FAT
   відтворює незмінений FAT **побайтово**, і всі файли читаються рівно за
   заявленим розміром. `cmp_rootdir.py` показує рівно 3 змінені записи
   (доданий `PD2PAL.COM`, `AUTOEXEC.ORI`, новий `AUTOEXEC.BAT`) — і нічого
   більше.

> Виявлений і виправлений баг: `fat_fs.py` з 98Bridge у гілці FAT12 знищує
> таблицю (`word = (word & 0xF000) | val` для парних кластерів затирає молодший
> нібл сусіднього запису — 2550 з 4096 байтів змінювались). Тому
> `inject_paldump.py` серіалізує FAT **своїм** кодом (`fat_serialize`), а
> `verify` перевіряє round-trip перед будь-яким записом.

## 4. Що ще НЕ доведено і чому

**`PALDUMP.COM` жодного разу не виконався.** Програма зібрана, покладена на
образ, `verify` проходить — але гість її не запускав.

Причина не в програмі й не в інжекторі:

* автоматичний запуск упирається в **меню завантаження PC-98**
  (`1: MS-DOS 6.20`, `2: …`, `4: SCSI`), яке чекає натискання клавіші.
  У неінтерактивних прогонах воно не проходиться: палітра весь час лишається
  BIOS-дефолтною (`000 00a 0a0 … fff`), а `AUTOEXEC.BAT` не виконується;
* `AppActivate` + `SendKeys` з PowerShell у DOSBox-X не доходять (перевірено
  4 рази: екран міняється, та AUTOEXEC не запускається);
* `EXIT`/`SHELL_EXIT` для дебагера не існують (`Debugger command not
  recognized`), тому коректно завершити емулятор із MCP не виходить.

**Крок, який це закриває (1 прогону руками):** завантажити `_hdi_test\pd2s_inj.hdi`
і **самому** натиснути `1` у меню. Тоді:

* `Z:\PALDUMP.COM Z:\PD2PAL.DAT` у `AUTOEXEC.BAT` має створити
  `PD2PAL.DAT` у робочій теці **одразу на хості** (`Z:` — це вбудований диск
  DOSBox-X, що вказує на `-working-dir`), без жодного write-back;
* якщо файл з'явиться — шлях «дампер усередині гостя» доведений повністю.

## 5. Практичний висновок

* Треба **палітру екрана гри зараз** -> `PC98 DACPAL` через MCP (§1A). Це
  працює і дає всі 16 записів DAC, разом із тими, яких немає на екрані.
* Треба **справжня, незмінна** палітра -> дампер у гості (§4) або `.pal` зі
  скріншота (§1B).
* Треба **гра з правильною палітрою** -> `pd2extract.py --pal out\game.pal`.

**Залізне правило:** усі досліди — тільки на копії (`_hdi_test\*`), оригінал у
`D:\Games\DOSBox-X\PD2S.HDI` не чіпати. `inject_paldump.py restore` повертає
`AUTOEXEC.BAT` з `AUTOEXEC.ORI` і прибирає `PD2PAL.COM`/`PD2PAL.DAT`.
