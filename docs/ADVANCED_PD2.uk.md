# Advanced Power Dolls 2 (1996) — розбір образів `.fdd`

## 1. Що це за версія

Advanced PD2 — **не самостійна гра, а патч-надбудова над базовою Power Dolls 2**.
Докази з самих дисків (диск 2, файл `PD2DT.IDX` — насправді фрагмент коду, але
поруч у контейнері лежить текстовий makefile):

```
.SILENT
.SUFFIXES : .idx .bnd .org .chg
pd2dt.idx : MES2.PCK WMES2.PCK INIT2.PCK NPC2.PCK SMAP1.PCK \
            DATAU.PCK MUNIT.PCK TUNIT.PCK WEAPON.PCK MMAP1.PCK \
            CHARA.PCK FACE.PCK DFACE.PCK EVKAO.PCK MAP_CHG.PCK \
            MISSONSD.PCK MISSONMD.PCK MISSONHD.PCK MISSONPD.PCK MISSONCD.PCK \
            EVENT.PCK ARMS.PCK SCORE_N.PCK \
```

Тобто установлювач **збирає** нові файли з наявної інсталяції PD2 за правилами
`.org`/`.chg`/`.idx`/`.bnd`. Файли на дисках названі як файли базової гри
(`PD2SHELL.EXE`, `TACTICS1.EXE`, …), але їхній вміст — фрагменти/патчі, а не
готові EXE (MZ є лише в `GO.EXE`, `BRIEF2.EXE`, `BRIEF3.EXE`).

## 2. Розкладка образів `.fdd` (BPB немає — відновлено з даних)

| параметр | значення |
|---|---|
| каталог | `0xD7FC`, 192 записи по 32 байти |
| перший кластер | `+0x1A` (u16), розмір | `+0x1C` (u32) |
| область даних | `0xEFFC`, кластер **1024** байти, `spc=1` |
| суміжність | усі файли суміжні: `cluster[k+1] = cluster[k] + ceil(size/1024)` (перевірено 17/17 пар на диску 1) |
| особливість | образ **не має перших 4 байтів** диска: справжній завантажувальний сектор починався б за `-4`; на дисках 4–8 його копія лежить за `0xC3FC` |
| розміри | 1 092 604 / 763 900 / 765 948 / 1 311 740 ×5 / 1 038 332 байт |

BPB немає взагалі (перший сектор — `VFD1.00` + нулі), тому `tools/img_extract.py`
отримав детектор «FAT без BPB»: він знаходить каталог, підбирає кількість
записів (16…256) і розмір кластера за **суміжністю файлів** та за тим, щоб
`.EXE`-записи справді починалися з `MZ`, а дані заповнювали образ до кінця.

Контроль: `GO.EXE` (диск 1) = `MZ`, `BRIEF2.EXE` (диск 2) = `MZ`,
`PD2DT.000…005` = `BI` («BIGFILE») — усе збігається.

## 3. Вміст дисків

| диск | вміст |
|---|---|
| 1 | установлювач і перші модулі: `INST.EXE`, `HD_INST.SCR`, `GO.EXE` (справжній EXE), `PD2SHELL.EXE`, `CONVERT.EXE`, `BRIEFING.EXE`, `TACTICS1.EXE`, `STARTUP.EXE`, `CONTROL.EXE`, `MAKEINIT.EXE`, `REPORT.EXE`, `KABE3.GCP`, `FONT_ANK.DAT`, `EMI/NARU/SARI/CDP.COM` |
| 2 | `BRIEF2.EXE` (MZ), `TACTICS2.EXE`, `REPORT2.EXE`, `PD2DT.IDX`, `OPENING.EXE` |
| 3 | `BRIEF3.EXE` (MZ), `TACTICS3.EXE`, `REPORT3.EXE`, `UNINST.EXE`, `DFACE2.PCK`, `COMMENT.TXT` |
| 4–8 | по одному тому контейнера: `PD2DT.000` … `PD2DT.004` (по 1 250 304 байти) |
| 9 | `PD2DT.005` (976 796 байт) |

`PD2DT.000…005` — шість частин **одного логічного контейнера** `BIGFILE`
(7 228 316 байт), усередині — бандл `PD2DT.BND`.

## 4. `PD2DT.BND` — розв'язано: це проста збірка + 24-байтова таблиця членів

Advanced PD2 не постачає файли даних гри. Він постачає **одну збірку** й
**таблицю вмісту**, і цю пару вже розкодовано:

```
PD2DT.IDX   плаский масив 24-байтових записів, без заголовка
    +0..15   ім'я члена, добите NUL (ASCII, без шляху)
    +16..19  розмір члена, u32 little endian
    +20..23  зсув члена в .BND, u32 little endian

PD2DT.BND   сира конкатенація, яку описує таблиця
```

`169` записів, і розкладка **точна**: `offset[k] + size[k] == offset[k+1]` для
кожного k, а останній член закінчується на останньому байті збірки
(7 228 225 із 7 228 225). Ні стиснення, ні заголовка, ні вирівнювання. Таблиця
до того ж самоперевірна: хибний крок запису, порядок полів чи ендіанність
одразу видно як пропуск, перекриття або вихід за межі.

Раніше таблицю членів шукали *всередині* збірки й знаходили там рядки
`BIGFILE` / `PD2DT   BND`. Вони належать даним самого установлювача, які теж є
членом (`SAVEDATA.ORG`, `MAKEFILE`; сам `PD2DT.IDX` під час інсталяції
генерується заново) — саме тому контейнер і не піддавався.

```
python pd2bnd.py --idx PD2_3/PD2DT.IDX --bnd PD2_3/PD2DT.BND -o out/apd2
python pd2sweep.py --image APD2.hdi -o out/apd2-sweep     # робить це автоматично
```

| що це за 169 членів | кількість |
|---|---|
| архіви `.PCK` | 74 |
| display-list'и `.GCP` | 39 |
| картинки `.ASK` | 9 |
| «сирі блоки» `.SLD` | 6 |
| `.DAT`, `.CMD`, `.MID`, `.CFG` | 37 |
| `MAKEFILE`, `TIMECHK`, `SAVEDATA.ORG/TMP` | 4 |

Це весь набір даних гри: `CHARA`, `FACE`, `DFACE`, `EVKAO`, `ARMS`, `WEAPON`,
набори `M_CLR*`/`AMAP*`/`SMAP*`/`MMAP*`/`OP3MAI_*`/`ADOPWI_*`/`OP_PL*`, архіви
`MISSON*`/`SCORE_*`, усі display-list'и `KABE*`/`K_BLANC*`/`BUSOU_*`/`PLAN_*` —
і **екрани, яких немає в жодному іншому релізі**: `GAMEOVER.GCP`, `SINGLE.GCP`,
`M_FAIL.GCP`, `AD_END.PCK`, `APD_STF0..3`, `KOKUPI3/4`, `0OPHA3`, `OPHUAN3`,
`AMAP1..3`. Після розділення збірки перебір `APD2.hdi` знаходить **546 картинок**
замість двох контейнерів, що лежать на диску окремо.

## 4a. Advanced PD2 змінив і формат портретів

У базовій грі `CHARA.PCK` містить 38 display-list-блоків
([`DISPLAYLIST.md`](DISPLAYLIST.uk.md)). У збірці ті самі 38 слотів містять
**звичайні растери** — `u32 size; u16 x,y,w,h` дає `19200 = 160*240/2`, а `x,y` —
це позиція на екрані 640x400 (`0`, `160`, `320`, `480`), тобто чотири портрети в
рядку. 27 із 38 слотів є картинками в обох релізах.

Малюнки не ті самі, тож це два взаємодоповнювані джерела, а не перехресна
перевірка:

## 5. Відкрите

> **Оновлено.** Шлях «поставити через рідний установлювач» більше не відкрите
> питання: готовий образ `_dbg\hdd\apd2_dos.hdi` (40 МБ, NEC MS-DOS 6.20, 42.5 МБ
> вільно), робочий `_dbg\run_apd2_install.bat` і перелік підводних каменів
> (`-fs none` не монтує; гість бачить HDD як `D:`) — див.
> [`APD2_INSTALL.uk.md`](APD2_INSTALL.uk.md).

1. **Правила патча `.org`/`.chg`.** `PD2DT.IDX` — це *результат* правила
   установлювача `.idx : .bnd .org .chg`; отже, у збірці вже лежить зібраний
   payload, і `pd2bnd.py` дістає його без знання семантики патча. Розкодувати
   `.org`/`.chg` потрібно лише для байт-у-байт відтворення інсталяції.
2. **Як диски ділять збірку.** Набір `.fdd` несе `PD2DT.000…005`
   (7 228 316 байт разом), а HDI-реліз постачає один `PD2DT.BND` (7 228 225).
   Обидва використовують ту саму 24-байтову таблицю; 91-байтова різниця між
   збірками не пояснена.
